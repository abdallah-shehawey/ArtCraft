# ArtCraft contributions

One place for my contributions to the [Craft App Suite](https://github.com/storytold). Each folder is a Git submodule pinned to the contribution commit on my fork; each project keeps its own history, licence and upstream pull request.

What the changes do:

- On Linux, windows reopen at their last size, or maximized, at any interface size (150% included), and Restore after a maximized restart returns to the last normal size. Before, WordCraft at 150% shrank on every restart.
- The eframe window store is disabled for runs without preferences and for the affected apps' control-channel runs. SoundCraft and VectorCraft also keep control-run geometry out of their legacy preferences. eframe also finishes writing the window before calling the app's exit hook, including GridCraft's macOS hook that ends the process.
- On GNOME Wayland, where the compositor draws no frame, a native Wayland window with the system frame gets standard Adwaita minimize, maximize and close buttons instead of winit's fallback (FilmCraft's looked broken). Not every app shows them by default: WordCraft, FilmCraft, DeckCraft, SoundCraft, DesignCraft, CADCraft and GridCraft open through XWayland, where GNOME draws the frame, unless `<APP>_WAYLAND=1`; PhotoCraft, PdfCraft, VectorCraft, FigCraft and the launcher draw their own title bar there; and LightCraft's frame is another contributor's PR ([storytold/lightcraft#1928](https://github.com/storytold/lightcraft/pull/1928)).
- LightCraft and the ArtCraft Launcher get a persistent interface size (Auto, or 50–300%); the other apps already had one.

The shared changes live in [storytold/egui#3](https://github.com/storytold/egui/pull/3). The thirteen app PRs that update the egui fork currently pin `69750b7` from that work; its later Windows follow-up awaits review and a durable dependency update. LightCraft already keeps its own window placement, so its PR is the interface size alone.

## Review follow-up — 29 Oct 2026

The new maintainer requests and the six GitHub notification emails were checked against the current pull requests. Five contribution branches had conflicts with their live target refs; their resolutions keep both the upstream changes and the contribution behavior. SoundCraft also gains profile isolation for native window state. Later upstream updates were kept mergeable by leaving their status headings and history insertion points intact; those final documentation and contributor-order adjustments leave application source unchanged.

- The [Windows review of CADCraft](https://github.com/storytold/cadcraft/pull/2194#pullrequestreview-5693289194) reproduced a maximized-rectangle overwrite in the shared backend. winit sends a move event before its cached maximize flag is updated by the following resize message. The shared fix reads the native Windows show state before recording normal geometry. The Windows regression fails with the old cached-only decision and passes with the fix; all 76 Windows egui-winit unit tests pass under isolated Wine/Xvfb. This is additional automated evidence; the updated fix has not been exercised on native Windows hardware or macOS.
- SoundCraft keeps eframe's app.ron inside the selected settings directory. Missing settings directories, no-preferences runs and control sessions disable native persistence; the profile-isolation regression covers these cases.
- EffectCraft follows the [maintainer's request](https://github.com/storytold/effectcraft/pull/2461#issuecomment-6488439800): it retains only its existing window.json/Tracker store, skips saved geometry in control sessions, includes upstream's macOS quit change #1762, and removes the review/integration banners. FigCraft also removes the two banners requested by its maintainer while preserving its existing progress records.
- The launcher keeps both the new Author-column translations and its interface-size translations. Native Auto starts and windows opened from the tray discard legacy zoom, and the percentage control is labelled for screen readers. GridCraft discards legacy widget memory before applying its own preferences while preserving native-window storage. The review claim that its pinned backend ignores `persist_window` is stale: `69750b7` already guards both startup paths and has a regression test. GridCraft and VectorCraft retain the latest upstream changes, contributor entries and native-window policies through their conflicts.

## Get the code

```sh
git clone --recurse-submodules https://github.com/abdallah-shehawey/ArtCraft.git
```

Cloned without `--recurse-submodules`? Run `git submodule update --init`. The submodules are pinned to the commits above; `.gitmodules` names each contribution branch.

## How it was checked

The contribution branches for all fourteen apps were checked on Fedora 44 (GNOME 50) on 26 Oct. Checks used each app's `cargo xtask ci` or its equivalent steps; PhotoCraft's steps were run individually because cargo-nextest is unavailable. Each PR records the commands, known machine-specific skips and remaining failures. WordCraft and EffectCraft include failures reproduced on their upstream baseline; PhotoCraft retains a laptop GPU timing failure. These are not reported as passing suites. The shared change was also run natively at 150%: repeated normal and maximized reopens, Restore after a maximized restart, and real clicks on the GNOME Wayland caption buttons. macOS and Windows were not run.
